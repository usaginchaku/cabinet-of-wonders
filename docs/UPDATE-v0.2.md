# v0.2: 配置を試し、反応を見て投資する

## 今回の変更

- 床のホバーは配置中だけ仮表示を動かす。クリック／タップで候補を固定し、「ここに置く」で保存する。移動中にほかの床を横切っても候補は変わらない。別の床をクリックすると選び直せる。Enterで候補を選ぶと確定ボタンへフォーカスを移す。
- 仮表示は展示・装飾の形、配置可否、区画、営業利益の差、隣接組数を示す。キャンセルで所持金・配置は変わらない。
- 通路のスイッチで入口から到達できる床を表示する。すべての展示・設備の隣に通路が必要。壁の絵やランプは装飾で、前を塞いでも経済効果は変わらない。館の展示照明は全体に効く。
- スマホの収蔵庫は190pxの横スクロール棚。館の領域と分離し、覆わない。収集館タブは全体を見る、設備・料金ボタンは管理パネルを開く。品の詳しい説明と導入ガイドは必要なときに開く。
- 営業は標準60秒。1×・2×・4×、一時停止、途中閉館の確認。確認・ヘルプ・非表示タブでは進行を止める。閉館確認を取り消しても精算しない。
- 来館者の感想は実際の混雑、料金、客層との相性、隣接、テーマ展示から作る。短い声を館に、判断根拠を営業記録の詳細に表示する。個々の客が独立した欲求や財布を持つシミュレーションではない。訪問アニメーションは到達可能な床を往復する。
- 調査担当は900 Gで採用。Lv.1で開館中の出発と受入+4人。調査2回と650 GでLv.2（日数−1、最短1日）。調査5回と1,400 GでLv.3（全展示の魅力+15%）。人件費は順に60/90/140 G。育成前に次の人件費を表示する。採用前・v0.1で完了した調査実績も引き継ぐ。
- 開館中の調査出発は残り営業時間の割合だけ当日分を進める。帰還までの表示は残り閉館回数。調査隊は1隊を維持する。
- 同じテーマを3点以上、合計Lv.6以上展示すると魅力+12・満足度+3。3テーマを独立に完成できる。完成時に通知する。展示を外したら効果も外れる。増築は20→30→42→56区画。

工房の小仕事は再起用として100 Gを保証し、営業を休む代わりに調査・修復を進める。休館日の人件費を取らず、過去の調査経験も失わせない。利益の大きい通常営業との選択であり、賃金による詰みを避ける仕様とする。

## 参考資料と適用範囲

- [Tynan Sylvester — The Simulation Dream](https://www.gamedeveloper.com/design/the-simulation-dream): プレイヤーが読み取れるフィードバックを重視する解説を参照。見えない複雑な計算を増やすより、仮配置の利益差・通路表示・客の声で今の計算を判断に使えるようにした。
- [Guillaume Pierre — We Built This City on Bits 'n Maps（GDC 2024）](https://www.gdcvault.com/play/1034347/We-Built-This-City-on): 公開セッション概要の Maps / Networks & Globals / Agents / Building-to-Building connections を参照。講演動画の視聴はしていない。本作では既存の通路探索・館全体の指標・隣接効果を可視化する整理に使った。

この2資料は特定のカイロソフト作品の内部実装を説明するものではない。面白さの保証として引用せず、読める因果関係と投資の選択を作る設計上の参考にした。難易度の長期的なプレイ評価は今後も必要。

## セーブと公開

- localStorageキー `curio-museum.save.v1` とサイトURLは維持する。内部形式を2に移行する。
- v1で営業途中なら18秒中の進行割合を60秒へ換算。既存の収集品、配置、資金、修復、調査、履歴を保持する。
- 旧形式で収集した初期4点以外の品数を、完了した調査実績として引き継ぐ。すべての品を集めた人も育成できる。
- 初めてv2を保存する際、移行前の有効な原本を `curio-museum.save.v1.before-v2` に保持する。以後の自動保存で上書きしない。設定からその原本を書き出せる。バックアップ保存失敗時は新しい主セーブで上書きせず、未保存を通知する。
- 一般の直前バックアップも維持する。外部同期はない。ブラウザデータ削除には耐えないのでファイル書き出しが必要。
- 公開は既存GitHub Pagesワークフロー。ランタイム配信ファイルの許可リスト、CSP、HTTPSを維持する。新規外部API・依存パッケージ・課金なし。
- v0.1のコードへ単純に巻き戻すと新形式を読めない。障害時はv2の読取互換を残した修正リリースを基本にする。移行前への復元が必要なら、現行進行も書き出した上で移行前原本を読み込む（進行が戻るため自動では行わない）。

## 独立レビュー

ユーザー許可済みのClaude Codeで読み取り専用レビューを実施。位置確定前のマウス／フォーカス移動による候補の上書きを修正して回帰テストを追加。採用直後の実利、帰還時期の表示、育成後の人件費、装飾配置後の戻り先、移行前データの保持も改善した。休館日の人件費は上記の再起仕様として維持した。
