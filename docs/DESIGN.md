# 開発方針 / v0.1

## 目的と完成条件

「ゆけむり温泉郷」の施設づくり・来客を眺める楽しさ・再投資の循環を参考に、収集館と修復工房という題材で遊べる最小版を作る。画面は箱庭と主要操作を中心にし、ルール・説明・保存操作は情報ダイアログへ集める。

完成条件: 初回ガイドを使い、配置→営業→修復→再展示→改良ができる。新しい収蔵品の調査、増築、改良の分岐が実際の収益に効く。リロードで進行が戻る。デスクトップ・390×844相当のブラウザ画面で操作できる。

## 技術選択

HTML/CSS/ES Modules + SVGを採用。ネイティブアプリのインストールよりすぐ試せ、Canvasより展示と区画のアクセシブルな名前・キーボード操作を持たせやすい。小規模なゲームなので、UIフレームワークやビルド環境は導入しない。依存はローカルに収録したLucideのアイコン定義のみ。

- `engine.js`: 描画と独立した純粋な状態遷移、収益計算、通路探索、セーブ検証。
- `data.js`: 収蔵品・調査先・設備・客層。
- `art.js`: オリジナルSVGジオラマと展示品。
- `app.js`: 画面、入力、営業タイマー、チュートリアル、情報ダイアログ。
- `storage.js`: 自動保存とファイルの入出力。

## 経営の判断

固定順の6客層が日替わりで来る。次の営業の予測を常に示し、料金や展示の変更を見比べられる。隣接効果、受入人数、魅力、照明、評判を別の要素として扱う。高い料金は集客と満足度を下げ、高価な設備は維持費も増やす。改良は鑑賞 / 回転の方向を固定し、一律の正解にしない。

評判は集客倍率に反映し、高額料金で低い満足度が続くと集客も落ちる。希望人数が受入人数を上回った場合も満足度が下がるため、人気に合わせた設備投資が必要。来館希望・受入人数・利益・満足度を同じ準備パネルで比較できる。

極端な配置失敗で収集品を消さない。赤字で手持ちを超えた維持費は免除する代わりに評判を下げ、記録に示す。工房の小仕事は1日100 Gの再起手段。時間制限・強制広告・ガチャ・課金なし。

## 素材と演出

クリーム色・深緑・真鍮の操作部と、木床の切り抜きジオラマ。カイロソフトの固有キャラ・UI・素材は使用しない。ジョジョ関連は原作から着想した独自の模型として扱い、公式の人物関係や能力を勝手に追加しない。キャラ会話、常勤キャラクター、オンライン機能はこの版には入れない。

## 参考記事の適用

[Felix Rieseberg, How to be more ambitious](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/) を確認。実装を増やすことではなく「ゲームの一周を遊べる」を成果にする。元の状態遷移と数値を直接テストし、ブラウザの実操作・保存再読み込み・レスポンシブ表示で外部から検証する。経営シミュレーション、オンボーディング、アクセシビリティの観点を組み合わせる。

Better DesignのUI/UX指針を取得。部品キット取得時にHTTP 402（利用枠上限）のため、以降のMCPレビューも利用不可。外部契約・生成・公開は行わず、実画面とローカル検証で確認する。
