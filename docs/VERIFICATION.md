# v0.1 検証記録

実施日: 2026-10-18。Windows / Node.js 24 / インストール済みGoogle ChromeをPlaywrightで操作。テストは独立したブラウザプロファイルを使い、普段のブラウザのセーブには触れない。

## ロジック

`npm test` — 13件成功。

- 配置 → 営業 → 修復 → 展示 → 分岐改良のチュートリアル。
- 設備を先に改良しても、展示の改良手順が飛ばされない。
- 資金不足・二重操作・営業中の変更・工房の満員を拒否し、元の状態を保つ。
- 入口・重なり・範囲外・到達できない展示への配置を拒否。
- 隣接効果・鑑賞/回転の分岐が収益計算に反映される。
- 装飾の撤去・半額回収。収集品は維持する。
- 調査先が約束した品を一度だけ持ち帰る。工房改良で日数短縮。
- 全15品の収集と最大42区画への増築に100日未満で到達可能。
- タイマー決済は一度だけ。保存済み営業は経過時間から再開。
- JSON破損、重複ID、無効な修復/調査、通路違反、プロトタイプ名IDを拒否。保存された売上予測は信頼せず再計算。
- 保存障害時のデータ保持、無資金時の工房小仕事。

## ブラウザ操作

実行方法（PowerShell、サーバー起動済み）:

```powershell
$env:PLAYWRIGHT_MODULE_PATH = 'C:/path/to/node_modules/playwright'
node tests/browser.test.cjs
node tests/interaction.test.cjs
```

`browser.test.cjs` は11件。展示、重なった区画、収益、修復、改良、調査、リロード、ヘルプ中の時間停止、JSON書き出し/読み込み、不正ファイル拒否、タブ競合、破損からの復旧後のEsc、設備撤去、増築済みの描画を操作。

`interaction.test.cjs` は4件。44px以上の通常操作部、スマホの料金パネル、展示品と床のキーボード操作、フォーカス保持、開館のダブルクリック、営業途中のリロード、18秒の実時間決済、リセット確認を開いた後に他タブが更新した場合の保護。

画面: 1440×960、390×844（タッチ・モバイルをエミュレート）、横幅320 / 768 / 1280 / 1728。スクリーンショットと結果JSONは `artifacts/`。初期状態・営業中・収蔵庫・修復工房・展示詳細・長いヘルプ・増築後を確認。

## 経営バランスの確認

初期展示を変えず30日間営業する比較。各日の維持費を差し引いた累計で、調査・修復・設備投資は行わない。

| 入館料 | 累計利益 | 最終評判 | 来館者合計 |
|---|---:|---:|---:|
| 20 G | 4,770 G | 16 | 360人 |
| 30 G | 8,370 G | 19 | 360人 |
| 45 G | 5,040 G | 0 | 166人 |

調整前は45 Gの固定運用が11,430 Gを生み、評判低下の経済的影響が弱かった。評判の集客倍率を調整し、短期の高単価と長期の集客に差が出ることを確認した。全配置・全戦略の最適性を証明したものではない。
